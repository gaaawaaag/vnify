# G3 · register/entities

正式开发模块。仅标记内的文字属于提示词。

## register.entities

<!-- prompt:register.entities -->
## 人物

登记主角、重要配角、影响关键事件或需要持续追踪身份与关系的人物，以及重要的被提及者；只出场一次的人也可以重要。只作背景的店员、司机、群众不登记，转换时用 guest。

同一人物的不同叫法归入一行。同名、同职业或相似外貌只是线索，合并需要原文依据；身份尚不明确或原文刻意隐藏的不同身份分别登记，并在“公开节点”写明在哪里揭示为同一人。

每人一行：

- ID：英文字母开头的短 ID，只含字母、数字、`_`、`-`，全书不变。
- 初始称呼：首次出现时读者已知的称呼。
- 首见：最早能确认在提及或描写此人的来源编号。
- 改名：读者得知新名字的来源与新名字，按原文顺序，如“p000020 林舟”；日常昵称不算改名。
- 称呼：正文里指此人的叫法（全名、姓、名、绰号、亲属或职务称呼）。只有在原文特指此人时才指他的泛称（如“教授”“学长”）注明“泛称”。
- 颜色：#RRGGBB，人物之间容易区分。
- 身份：一句话，只写读者在首见时已知的身份。

## 地点

登记故事实际发生场景的具体空间，每处一行：ID、当时已知的空间名（同一建筑的不同空间可写作“宅邸·书房”）、首见。只在台词里提到、没有在那里发生场景的地方不登记。

人物、地点、称呼与外观都取自保留为正文的故事内容，首见与改名的编号指向相应事实出现的位置。

## register.additions

<!-- prompt:register.additions -->
## 续登

转换中遇到登记表没有的人物或地点，或合并各段登记时，按原文确定身份：

- 原文足以确认是已登记对象或其别称：沿用已有 ID，把新称呼补进称呼一列。
- 对情节重要、影响关键事件或需要持续追踪的人物，以及实际发生场景的新地点：新增一行。ID 与已有对象相同而实际是不同对象时另起 ID。
- 临时搭话者、背景群众：不登记，转换时用 guest 加当时已知的称呼。
<!-- /prompt -->
