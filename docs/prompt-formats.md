# 提示词写法

导演只写与模型无关的自然语言底稿；各生图模型需要的写法挂在生图预设上，在制作阶段由 agent 转换，生图时不再调用语言模型。

## 三层

1. **底稿**：导演写的画面描述、人物 face／body、差分变化。程序按 `image11.*` 模板组装成英文自然语言的文生图提示词、差分编辑提示词与参考图提示词（见 [prompts_v3 image](prompts_v3/image/tasks.md)）。这是“通用自然语言”，不需要转换就能发送。
2. **写法**：生图预设（image-presets.json）的 `format`：
   - `notes`：写给 agent 的改写要求，例如“用 danbooru 标签，逗号分隔”。留空表示直接发送底稿组装的提示词。
   - `edit`：差分以默认图编辑时发送什么。`instruction` 发编辑指令（适合指令式编辑模型、对话接口）；`full` 发差分的完整画面描述（适合 NovelAI 图生图这类不理解指令的模型）。NovelAI 预设默认 `full`，其余默认 `instruction`。
   - `refLabel`：附参考图时提示词里怎么称呼每张图，须含 `{n}`，如 `image {n}`、`图{n}`；留空不编号。
   - `transparent`：透明写法，见下方“模型直接出透明立绘”。
3. **改写稿**：agent 按写法把组装好的提示词改写成实际提示词，存在导演清单旁的 `formatted.json`（清单字段 `formatted`），按生图预设分开，记下改写时写法要求的指纹（`format`）和每条所依据的组装提示词的指纹（`source`）。改写要求或导演稿变了，或立绘的改写稿没有逐字保留一组取景句（英文 `image11.standing-framing` 或中文 `image11.standing-framing-zh`，改写 packet 的立绘条目以 `keep.en`／`keep.zh` 列出，`--apply` 也检查），对应的改写稿就不再使用：

   ```json
   {"version":1,"presets":{"<预设 ID>":{"format":"<指纹>","prompts":{"<任务 ID>":{"text":"…","source":"<指纹>"},"<任务 ID>#edit":{"text":"…","source":"<指纹>"}}}}}
   ```

## 制作预设挂载生图预设

制作预设的“生图方式”（`drawing`）二选一：

- **agent 生图**（`mode:"agent"`）：用 agent 宿主的生图工具。导演照常写底稿；`notes` 是给 agent 的写法说明（可空），agent 生图时按它和 `image-models/` 的模型说明调整措辞。旧的“提示词主体·自定义要求”迁移到这里。
- **挂载生图预设**（`mode:"presets"`）：`uses` 按用途（背景、CG、特写、封面、立绘、差分编辑）指定生图预设 ID。agent 开始制作时把它写进导演清单的 `imageScheme`，作为管理器里该作品生图方案的初始值；导演完成后，对挂载的、写了 `notes` 的预设逐个运行改写（`scripts/format-prompts.mjs`），分批提交。交付结果为完整配图时，agent 接着用 `scripts/draw-images.mjs` 按生图方案生成：与管理器同一队列，发送同一段文字（见下节），生成后立即绑定并记入生成记录；agent 逐张查看，有严重问题时写入手动改写再重画。

## 发送时选哪段文字

管理器生成一张图时，按顺序取第一段存在的文字：

1. 用户在管理器里手动改写的实际提示词（prompts.json，对所有预设生效）；
2. 所选生图预设的改写稿，且改写后写法要求与导演稿都没有变；
3. 底稿组装的提示词。

所选预设写了 `notes` 却没有可用的改写稿（换了预设、改过写法要求或导演稿）时照常生成，用第 3 项，并在资产页标出“未按此预设改写”；可以让 agent 补改写，或手动改。差分在 `edit:"full"` 时取文生图那一组（手动 → 改写稿 → 组装），不取编辑提示词。

## CG 的出场人物

导演为每张 CG 列出画面里的主要人物（`cast`，最多 3 人，见 [Director](director.md#cg)），每人一条 `look`（这张图里看得到的外观），画面描述里用 `@1`–`@3` 指代他们、写清各自在做什么。其余人物在画面描述里直接写外观。发送时程序按是否附上立绘补全：

- 附了立绘的人物：`@1` 写成“林 (image 1)”（编号按 `refLabel`，留空只写名字），开头先加 `image11.ref-cast`，说明这几张参考图依次是谁、脸和发型照参考图、衣着动作照文字；
- 所有出场人物列在 `image11.cast` 里，每人一行“名字（编号）: look”；没附立绘的只写名字与外观，画面描述里的 `@n` 也只换成名字。

所以同一份导演稿附不附参考图都能用。没有 `cast` 的 CG（之前的导演稿）照原样发送，不附参考图；程序不按正文推测画面里有谁。改写稿与手动改写同样保留 `@1`–`@3`：改写 packet 里的 CG 条目带 `cast`（标记、名字与外观），`--apply` 检查标记没有增减；人物说明那几行由程序生成，不在改写范围内。

## CG 附人物立绘

作品生图方案勾选“CG 附人物立绘作参考”（`imageScheme.cgReferences`）后，管理器画 CG 时按 `cast` 的顺序附上各人的已绑定立绘：每人取 CG 起点所穿差分的立绘，没有就用默认立绘；还没有立绘的人物只用外观描述。透明立绘垫白底后发送。

- 能收几张由预设决定，超出的人物只用外观描述：OpenAI 兼容预设开了“以默认图编辑”时最多 4 张（图像接口一张发 `image`、多张发 `image[]`；对话接口按顺序附在文字后）；ComfyUI 需要上传“参考图工作流”（提示词与尺寸同生图，立绘按顺序交给最多三个“加载图像”节点，人物少于节点数时，多出的加载图像节点连同只为它服务的节点在发送前去掉，接收它的输入须是可选的，如 Qwen 编辑编码器的 image2、image3），张数等于对应上的节点数；NovelAI 不发参考图，照常文生图。
- 生成记录写明 `mode:"reference"` 与所附人物。

agent 用宿主工具生图时按 `--jobs` 处理：CG 任务的 `prompt` 已按外观补全人物；`cast` 中有人登记了参考图时另给 `references` 与 `referencePrompt`（按参考图顺序编号为 image 1、image 2…）。与这里的管理器选项无关。

## 模型直接出透明立绘

生图预设的 `transparent` 表示生成结果已是透明背景：NovelAI V5 发透明参数，OpenAI 图像接口发 `background: transparent`，ComfyUI 表示工作流直接输出带透明通道的 PNG（如 Qwen Image 2.1）。直接生成透明图通常比生成后去背可靠：换装差分常与原背景色混淆，导致去背失败。

这类预设画立绘与立绘差分时，发送前处理提示词（手动改写、改写稿、组装稿都一样）：

- 组装稿里的纯色背景句（作品按“纯色背景后去背”写的）换成透明背景句；
- 预设写了透明写法（`format.transparent`，须含一处 `{prompt}`）时，背景句一并去掉，整段提示词（含固定正面）套进写法。Qwen Image 2.1：`This is an RGBA image with transparency. {prompt} The image has alpha channel and the background is transparent.`；文字里已含写法开头的不再套。差分的编辑指令也套。
- 背景、CG 等不受影响。

所以同一作品换成直接出透明图的预设，不用重写导演稿；改写要求（notes）里不必写透明背景的说法。差分编辑的底图按原样的透明 PNG 发送（NovelAI 图生图仍垫白）；ComfyUI 的“加载图像”节点把透明度单独输出为遮罩，要让模型看到透明底图，在工作流里用“合并图像与 Alpha”（Join Image with Alpha）把图像和遮罩接回 RGBA 再交给编码器，模型是否接受 RGBA 输入以其 ComfyUI 示例工作流为准。生成结果已透明时不再去背（按图片本身判断）。
